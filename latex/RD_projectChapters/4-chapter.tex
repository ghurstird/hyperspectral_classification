\section{Material and Dataset}
The performance of different models on a classification task in hyperspectral imaging (HSI) is highly dependent on the different features of the used dataset. These features include the model's spatial resolution, the level of class imbalance, and the number of samples in the dataset with labels. In this work, we use three benchmark datasets from the remote sensing literature, and each of these datasets has its own set of challenges.

\subsection{Data Structure and Storage}
All of these datasets have the same 3D structure and can be visualized as a hypercube, where the dimensions of the hypercube are the spatial dimensions (H and W) and the number of spectral bands (B). All datasets are stored as NumPy arrays (.npy) and are loaded in spatial patches to facilitate the training process. This supports the local spatial context and allows us to use the limited memory efficiently.

\section{Methodology}
The processing pipeline consists of three sequential phases: preprocessing, patch-based feature extraction, and learning. Each phase is connected to the next, and the characteristics of hyperspectral data are reflected in the design of each phase.

\subsection{Preprocessing and Dimensionality Reduction}
Hyperspectral cubes are made of hundreds of noises and correlated bands and can mislead learned features. Consequently, the cost of training can increase greatly. In order to mitigate this, three operations are done.

\begin{enumerate}
    \item \textbf{Global Min-Max Normalization:} In this step, the hyperspectral data is reshaped from a 3D hypercube to a 2D matrix. From here, the global minimum and maximum across all pixels and bands of the reshaped data are calculated. Each value is then rescaled per the new global minimum and maximum. Normalization of the bands was avoided to prevent variance loss.
    \begin{equation}
        \hat{x} = \frac{x - x_{\min}}{x_{\max} - x_{\min}}
        \label{eq:normalization}
    \end{equation}

    \item \textbf{Spatial Gaussian Filtering:} In this step the data is filtered using a Gaussian Filter. The value of $\sigma$ was set to 0.5 and was only applied to the spatial axes of the 3D hypercube. A value of zero was set for the spectral $\sigma$ ensuring that the relationships between the bands of the data were preserved.

    \item \textbf{Fixed-Component PCA:} In this step, PCA is applied with a value for $n\_components$ set to 30. Prior to this, a variance threshold of (99.5\%) was applied. However, for both the Salinas and Pavia University datasets, this resulted in 4-5 PCA components. This was insufficient for the input depths of the Convolutional Neural Networks and Vision Transformers. The processed hyperspectral data was then reshaped to $(H, W, 30)$ \cite{pedregosa2011scikit}.
\end{enumerate}

\subsection{Patch Extraction and Dataset Splitting}
From each pixel $(r, c)$ where \texttt{gt[r,c] > 0}, a $15 \times 15$  patch is sampled from the PCA cube, resulting in a sample of size $15 \times 15 \times 30$. All background pixels (label $= 0$) are omitted. A cube is padded $\lfloor 15/2 \rfloor = 7$ pixels on each side with reflective padding, allowing boundary pixels to be valid patch centers.

Patches are randomly split into training and test sets with \texttt{test\_size=0.1}, \texttt{stratify=y}, and \texttt{random\_state=42}. The resulting sample counts are given in Table~\ref{tab:split_sizes}.

\subsection{Model Architectures}
Two model architectures represent different yet complementary approaches to learning spectral and spatial features:
\begin{itemize}
    \item \textbf{3D-CNN:} With 3D convolution, spectral and spatial features are extracted simultaneously. The model is designed with convolutional blocks with batch normalization and ReLU activations. \cite{chen2016deep}.
    \item \textbf{Vision Transformer (ViT):} With a ViT, HSI patches are first linearized, then multi-head self-attention is applied to each spectral-spatial token. \cite{dosovitskiy2020image}.
\end{itemize}

\subsection{Supervised Learning Models}
All models in this paradigm learn only from the labeled portion of the training dataset. It is also the baseline model for measuring the performance of semi-supervised and federated models. 

\subsubsection{2D-CNN Supervised Model}
The 2D-CNN model uses $15 \times 15 \times 30$ patches and treats the 30 PCA components as channels. Convolutions in this model are applied over the spatial dimensions. 

\subsubsection{3D-CNN Supervised Model}
The 3D-CNN model uses volumetric convolutions that simultaneously span both the spatial and spectral dimensions.

\subsubsection{Vision Transformer (ViT) Supervised Model}
In the ViT, HSI patches are first linearized and then augmented with learnable positional encodings to retain their order \cite{dosovitskiy2020image}.

\subsection{Semi-Supervised Learning Models}
The collection of expert labeled pixel annotations is a long and costly process. Semi-supervised learning employs the extensive, yet unlabeled, pixel set as a training signal. The strategy combines self-training and curriculum learning to add to the labeled set progressively while containing the noise of pseudo-labels.

\subsubsection{Self-Training Strategy}
Pseudo-labeling self-training occurs in the following iterative manner:
\begin{enumerate}
    \item A small, labeled training sample set is used to initialize the model.
    \item Subsequently, predictions with confidence score are generated for the unlabeled sample set.
    \item The sample set is then augmented by the inclusion of highly confident predictions.
    \item The model is retrained on the augmented sample set.
    \item The process is repeated until a convergence criterion is met \cite{triguero2015self}.
\end{enumerate}

\subsubsection{Curriculum Learning Integration}
Curriculum Learning (CL) helps structure the training procedure by organizing data from the easiest to the hardest samples:
\begin{enumerate}
    \item \textbf{Easy Samples:} Training begins with samples that have good spectral data and clear pixels, allowing boundaries to be drawn that the model will not likely misclassify.
    \item \textbf{Medium Samples:} Pixels that have moderate spectral and spatial data will be introduced next.
    \item \textbf{Difficult Samples:} Samples that have unclear spectral data and difficult boundary pixels will be included in the training to further refine the model’s boundaries \cite{bengio2009curriculum}.
\end{enumerate}

\subsubsection{2D-CNN Semi-Supervised Model}
The structure of the model is the same as the supervised model, but the self-training process will continuously add confident pseudo-labeled patches, and curriculum learning will manage the order of these additions, reducing the impact of early introduced label noise.

\subsubsection{3D-CNN Semi-Supervised Model}
Pseudo-labels that are added will allow the 3D-CNN to learn a variety of spectral and spatial data beyond what is offered in the labeled data, and the order of curriculum training will prevent the model from becoming too focused on the loudest pseudo-labels.

\subsubsection{Vision Transformer (ViT) Semi-Supervised Model}
The large global receptive field and self-attention of the ViT model are advantageous in semi-supervision, as it allows the model to draw a connection between confident pseudo-labels and labeled data beyond a local context.

\subsection{Federated Learning Models}
In a federated learning model, a global model is trained without raw data moving towards a central server, as clients only send model updates after training on their own data. Here, a server-client model is used to represent federated learning, with three disparate datasets representing the independent client institutes \cite{mcmahan2017communication}.

\subsubsection{Federated Learning Framework}
The Federated Learning phenomenon utilizes the Federated Averaging (FedAvg) algorithm and works in the following manner:
\begin{enumerate}
    \item The central server starts off with a global model.
    \item Each client receives the global model and trains it locally on their own hyperspectral dataset for a predetermined number of epochs.
    \item Clients send the updated model back to the server (data is neither sent nor received, ensuring privacy).
    \item The server consolidates the updated model using the averaged weights from all clients.
    \item The revised global model is sent back to the clients.
    \item The process is repeated for as many rounds of communication as necessary until convergence is reached.
\end{enumerate}

\subsubsection{2D-CNN Federated Model}
Each of the clients (Indian Pines, Pavia University, and Salinas) builds an identical 2D-CNN model locally, using a set of hyperparameters which they all share. Weight averaging at the server integrates the spatial patterns of each dataset into a single global model. This is done while maintaining the privacy of the clients.

\subsubsection{3D-CNN Federated Model}
The 3D-CNN model’s training kernels cover the dataset-specific spectral training patterns. The global model after aggregation possesses a stronger spectral training patterns than any single dataset model, which is especially needed in remote sensing.

\subsubsection{Vision Transformer (ViT) Federated Model}
The training patterns at each client site are captured by the Transformer attention weights. After aggregation at the server, the global attention makes it feasible to work with the diverse spectral-spatial statistics arising from various clients.

\subsubsection{Privacy and Communication Efficiency}
The main privacy benefit of federated learning is that raw hyperspectral data does not leave client locations. However, the communication overhead between clients and the server is a real limitation.

Three methods help address this issue:
\begin{itemize}
    \item \textbf{Gradient Compression:} Model weights are compressed before sending them, thus saving bandwidth.
    \item \textbf{Local Training Epochs:} Clients perform a number of local training epochs (5-10 is typical) before sending model weights. This means fewer communication rounds overall.
    \item \textbf{Asynchronous Aggregation:} The server aggregates model updates from clients that responded first. This helps save time when contrasted with other methods, which wait for all participating clients to respond.
\end{itemize}

\subsection{Evaluation Metrics}
To measure classification performance, five common parameters are used. Let T Pc , F Pc , and F Nc denote the true positives, false positives, and false negatives for class c, and let N denote the total number of test samples.

\begin{itemize}
    \item \textbf{Overall Accuracy (OA):} Ratio of the number of correctly classified test pixels to the number of test pixels:
    \begin{equation}
        \text{OA} = \frac{\sum_{c} TP_c}{N}
    \end{equation}

    \item \textbf{Precision:} The fraction of test pixels that belong to class $c$ when predicted to be in class $c$, This is macro averaged:
    \begin{equation}
        \text{Precision} = \frac{1}{C} \sum_{c=1}^{C} \frac{TP_c}{TP_c + FP_c}
    \end{equation}

    \item \textbf{Recall:}  The fraction of class $c$ test pixels that were predicted to be in class $c$:
    \begin{equation}
        \text{Recall} = \frac{1}{C} \sum_{c=1}^{C} \frac{TP_c}{TP_c + FN_c}
    \end{equation}

    \item \textbf{F1-Score:} The harmonic mean of Precision and Recall.
    \begin{equation}
        \text{F1} = \frac{2 \cdot \text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}
    \end{equation}

    \item \textbf{Cohen's Kappa ($\kappa$):} The metric helps Overall Accuracy when measuring classification performance. Given the observed accuracy $p_o$ and the chance agreement $p_e$:
    \begin{equation}
        \kappa = \frac{p_o - p_e}{1 - p_e}
    \end{equation}
    A value of $\kappa = 1$ is perfect classification; $\kappa = 0$ is random classification.
\end{itemize}

\subsection{GUI and Multithreading Integration}
The models are available in a standalone desktop application built using PyQt6. Model inference is processed in a separate worker thread. This is separate from the main UI event loop. As a result, the UI remains responsive while the deep learning pipeline is processing a hyperspectral hypercube.
